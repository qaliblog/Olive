Plugins modify Olive's behavior and add new features. A plugin is one package with a server part, a TUI part, a GUI
part, or any combination.

```ts title=".olive/plugins/example/index.ts"
import { Plugin } from "@olive/plugin"

export default Plugin.define({
  id: "example",
  async setup(ctx) {
    await ctx.storage.set("loaded", true)
  },
})
```

Migrating an existing Olive 1 plugin? Follow the [V1 plugin migration guide](/build/plugins/migrate-v1).

## Parts

Each part is an export of the package. Every part's SDK comes from the one `@olive/plugin` dependency.

```json title="package.json"
{
  "name": "olive-acme-plugin",
  "version": "1.0.0",
  "type": "module",
  "exports": {
    ".": "./src/index.ts",
    "./tui": "./src/tui.tsx",
    "./gui-experimental": "./dist/gui-experimental.cjs",
    "./rpc": "./src/rpc.ts"
  },
  "files": ["src", "dist"],
  "dependencies": {
    "@olive/plugin": "latest"
  }
}
```

- **Server** (`.` or `./server`) runs in the Olive server with `@olive/plugin`. It adds tools, hooks,
  integrations, commands, and agents. See [Server](/build/plugins/server), or [Effect plugins](/build/plugins/effect)
  for the Effect API.
- **TUI** (`./tui`) runs in the terminal UI with `@olive/plugin/tui`. See [TUI](/build/plugins/cli).
- **GUI** (`./gui-experimental`) runs its `setup` in every Olive Desktop window and its `main` in the desktop app's
  main process, with `@olive/plugin/gui`. See [GUI](/build/plugins/gui).
- **RPC** (`./rpc`) is a typed contract that the server part implements and the other parts and clients call. See
  [RPC](/build/plugins/rpc).

The plugin's `id` comes from its server part's `Plugin.define`. A package with a GUI part and no server part takes its
package name (or a local directory's name) as its `id`. A TUI part declares its own `id`; a GUI part declares none and
takes the plugin's.

## Load

Plugins under `.olive/plugins/` load automatically, like the local example above. To load published packages or
plugin directories from other locations, add them to `plugins` in `olive.json(c)`:

```jsonc title="olive.jsonc"
{
  "$schema": "https://olive.ai/config.json",
  "plugins": [
    "olive-acme-plugin",
    "olive-acme-plugin@1.2.0",
    "@acme/olive-plugin",
    "./plugins/local",
    "../shared/plugin",
    "/absolute/path/plugin",
    "file:///home/me/plugins/local",
    {
      "package": "@acme/olive-plugin",
      "options": {
        "agent": "reviewer",
        "strict": true,
      },
    },
  ],
}
```

- One entry loads every part. The TUI loads the TUI parts of the plugins its server loads, and Olive Desktop loads
  the GUI parts of the plugins in your global `olive.json(c)`.
- A package with only a TUI part goes in [`cli.json`](/cli/plugins) instead.
- A local plugin directory with a `package.json` `name` and `exports` loads its parts through them, like the published
  package. Without them, it uses file names at its root: `server` (else `index`), `tui`, and `rpc` with a `.ts`,
  `.tsx`, or `.js` extension, and `gui-experimental.cjs` (or `.js`).
- See [Configure plugins](/plugins) for more loading and configuration options.

## Publish

A published plugin is an npm package with the `package.json` above. Its parts use the same default exports as a local
plugin.

```bash
npm publish
```

- Export `./rpc` when other plugins and clients should import your [RPC contract](/build/plugins/rpc) without loading
  your implementation.
- Build the GUI bundle before you publish, and include it through `files`. See
  [Build the bundle](/build/plugins/gui#build-the-bundle).
- Use versions compatible with the Olive release you target, and test the installed package, not only a
  workspace-linked copy. Publish a compatible plugin update when you adopt a newer API contract.
